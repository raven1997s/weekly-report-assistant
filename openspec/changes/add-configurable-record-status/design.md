## Context

工作记录目前使用可配置的项目和工作类型字符串。状态属于同一类单选元数据，但还需要兼容旧记录、计划转换和固定的周报模板。

## Goals / Non-Goals

- Goals:
  - 复用现有设置存储和选择交互
  - 支持记录状态配置、选择、展示和筛选
  - 保持历史数据和现有周报模板兼容
- Non-Goals:
  - 不实现百分比进度
  - 不实现多状态标签
  - 不实现状态流转限制或自动化工作流
  - 不改变下周计划的标签格式

## Decisions

- Decision: 状态以显示文本直接存入 `records.status`，与 `project`、`workType` 保持一致。
- Decision: 状态配置存入现有 `settings` 表的 `recordStatuses` 键，不新增配置表。
- Decision: 默认状态为“待开始、进行中、待验证、已完成、已阻塞、已暂停”。
- Decision: 新建手工记录优先使用“已完成”；若配置中不存在“已完成”，使用配置列表第一项；配置为空时回退为“已完成”。
- Decision: 历史记录的 `status` 为空时按“已完成”读取和展示，不批量改写历史数据。
- Decision: 筛选选项合并当前配置与现有记录中的状态，确保配置删除或改名后旧记录仍可筛选。
- Decision: 计划转换生成的工作记录默认使用“待开始”。
- Decision: 周报仅在本周工作记录标签末尾追加状态，不改变章节、排序和下周计划格式。
- Alternatives considered: 独立状态表和状态 ID 可支持重命名级联，但会增加关联、迁移和管理成本，当前字符串配置已经足够。

## Risks / Trade-offs

- 状态重命名不会自动修改历史记录，因此筛选中可能同时出现新旧名称；通过合并历史状态保证数据可见。
- 字符串状态无法表达严格工作流；当前需求只需要记录和筛选，不增加状态机。

## Migration Plan

1. 为 `records` 表增加可空 `status` 字段。
2. 初始化 `recordStatuses` 默认设置，但不覆盖用户已有设置。
3. 读取旧记录时将空状态映射为“已完成”。
4. 回滚时可停止读写 `status`，已有列和设置数据无需删除。
