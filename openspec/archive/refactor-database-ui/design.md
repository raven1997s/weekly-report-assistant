# 设计文档：数据库管理 UI 重构

## Context

当前数据库管理页面使用单一通用表格展示 5 种不同类型的数据表，导致：
- 用户体验差：每个表字段不同，难以统一优化
- 视觉设计陈旧：缺乏现代 UI 元素
- 代码维护困难：所有逻辑集中在单一组件

## Goals / Non-Goals

### Goals
- 提升页面美观度和现代感
- 改善数据浏览和筛选体验
- 保持功能完整性（只读查看）
- 代码可维护性提升

### Non-Goals
- 不增加数据编辑功能（保持只读）
- 不修改后端 API 接口
- 不拆分为多个路由页面（保持单页体验）

## Decisions

### 决策 1：单页重构而非多页拆分

**选择**：在单一页面内优化布局和样式，不拆分为多个路由

**理由**：
- 用户已习惯当前的表切换交互
- 减少实现复杂度
- 避免路由变更带来的额外工作

### 决策 2：采用 Tab + 卡片混合布局

**布局结构**：
```
┌─────────────────────────────────────────────────────┐
│  页面头部（标题 + 描述）                              │
├─────────────────────────────────────────────────────┤
│  表切换器（Segmented Control 风格）                  │
├─────────────────────────────────────────────────────┤
│  搜索栏 + 筛选按钮（优化后的紧凑布局）                │
├─────────────────────────────────────────────────────┤
│  数据展示区（根据表类型自适应）                       │
│  ┌─────────────────────────────────────────────────┐│
│  │ 工作记录/下周计划：紧凑表格 + 悬浮预览           ││
│  │ 周报归档：时间线卡片布局                         ││
│  │ 设置：键值对卡片网格                             ││
│  │ 定时任务：状态指示卡片                           ││
│  └─────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────┘
```

### 决策 3：样式现代化策略

**视觉升级点**：
1. **表切换器**：从普通按钮改为 Segmented Control（分段控件）
2. **搜索栏**：添加玻璃态背景 + 柔和阴影
3. **表格**：减少边框，使用底色区分行
4. **卡片**：圆角、微阴影、悬浮效果
5. **动画**：表切换时的淡入淡出、行悬浮高亮

## UI 组件升级规划

### 1. 表切换器（SegmentedControl）
```scss
// 新样式
.table-selector {
  background: var(--bg-secondary);
  border-radius: $radius-lg;
  padding: 4px;
  
  .table-tab {
    border-radius: $radius-md;
    transition: all 0.2s ease;
    
    &.active {
      background: var(--bg-card);
      box-shadow: $shadow-sm;
    }
  }
}
```

### 2. 搜索筛选区
```scss
.search-filter-bar {
  background: var(--bg-card);
  border-radius: $radius-lg;
  padding: $spacing-3;
  box-shadow: $shadow-xs;
}
```

### 3. 数据表格增强
- 移除外边框，使用行底色区分
- 表头固定时添加阴影
- 单元格内容添加 tooltip
- JSON 字段添加预览面板

## Risks / Trade-offs

### 风险 1：样式变更可能影响其他页面
- **缓解**：使用 scoped 样式，不修改全局变量

### 风险 2：动画可能影响性能
- **缓解**：使用 CSS 原生动画，避免 JavaScript 动画

### 风险 3：渐进式重构可能导致不一致
- **缓解**：一次性完成所有样式更新
